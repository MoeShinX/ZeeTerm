# 面向用户的更新说明

这个目录放每个版本的**更新说明**，文件名是版本号，例如 `0.4.0.md`。发版时 `scripts/release.ps1` 会优先用它作为 `latest.json` 里的 `notes`，用户在更新窗口里看到的就是这份文字（同时也是 GitHub Release 页的正文）。没有这份文件时脚本才退回 `CHANGELOG.md` 里的 `## [<版本>]` 一节，见 `docs/RELEASING.md` 的"更新说明"。

## 怎么写

写给普通用户看：说清"能做什么 / 有什么变化"，几条要点就够了。不要写脚本名、内部实现、提交号，那些留在 `CHANGELOG.md`。

建议的结构：一句话概述，加 `### 新功能`、`### 改进`、`### 修复` 三节（没有的就省掉），每节几条，**每条一行**。

```markdown
这一版重新设计了更新窗口，并修复了几个连接问题。

### 新功能

- 更新窗口能看清更新内容，还可以选中复制。
- 新增「跳过此版本」。

### 改进

- 下载更新时显示已下载大小和速度。

### 修复

- 修复断网重连后终端偶尔不刷新的问题。
```

## 能用什么

更新窗口把说明渲染成 Markdown：标题（`###`）、列表（可以嵌套）、**粗体**、`行内代码`、代码块、分隔线、表格都支持。出于安全：

- HTML 不会被执行，原样显示成文字；
- 图片不会加载（显示替代文字），不要靠图片说明问题；
- 只有 `https://` 链接能点开，用系统浏览器打开；`http://`、`mailto:` 等其他链接只显示文字。

## 注意

- 文件用 UTF-8 编码，带不带 BOM 都可以。
- 已经发布的版本不要回头改这里的文件：更新窗口显示的是发布时写进 `latest.json` 的那一份。
